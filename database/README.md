# 数据库说明

数据库表结构依据上级目录的《东软体检项目系统-实践手册》第 9–12 页整理，使用 MySQL 8 与 `utf8mb4`。

- `01_schema.sql`：建立手册中的 11 张业务表及用于预约排班的 `hospital_schedule` 表，并配置主键、非空和外键。选择空的 `tijian` 库执行；不会删除已有表，重复执行会报表已存在。
- `02_seed.sql`：一次性插入虚构的医院、套餐、检查项目及医生教学数据。只能在对应表为空时执行一次；重复执行可能触发主键冲突。示例检查范围不是医疗依据。
- 手册 `cidetailedreport.ciId` 的说明是所属检查项报告编号，因此本实现将其作为外键关联 `cireport.cirId`；命名保留手册原样，后端需遵守此约定。
- 手册原密码字段为 `varchar(20)`；现扩容为 `varchar(100)` 保存 BCrypt 哈希。旧明文账号在首次成功登录时转换；示例医生账号 `doctor01`、密码 `123456` 仅供本地教学。
- `06_demo_patients.sql`：额外添加 5 个虚构患者账号、5 条预约、2 份已归档报告、2 个演示机构及配套套餐和检查项；不会修改原有记录。本机已执行，不要重复执行。

手册以图片给出字段，SQL 已据此录入；后端开发时应继续核对接口和数据库字段是否一致。

- `03_password_hash_migration.sql`：将旧数据库中的两个密码字段扩容；不删除账号数据。本机数据库已执行。

- `04_family_appointment.sql`：向旧库的 `orders` 添加体检人快照字段；原有记录不变。新建库时 `01_schema.sql` 已包含这些字段，不要重复执行。
- `05_hospital_schedule.sql`：为旧库新建每周排班表，并为示例医院配置周一至周五每天 20 个名额。新建库时由 `01_schema.sql` 和 `02_seed.sql` 完成，不要重复执行。

本机库已执行 03、04 和 05 迁移。家属预约的订单仍归登录账户所有，体检人信息存入订单；原有无快照记录使用预约账户信息显示。示例排班是教学配置，不是实际医疗机构的数据。其他医院需配置自己的 `hospital_schedule`，尚无排班管理页面和节假日例外规则。

## 演示数据使用

- 用户演示账号：`19900000001` 至 `19900000005`，密码均为 `Demo123456`。其中 01 和 05 可直接查看已归档报告，02、03、04 有待医生处理的预约；03 是家属预约。
- 原有医生 `doctor01` 不变；新增演示医生 `doctor02`、`doctor03`，密码为 `Demo123456`。所有资料、证件号、检查结果和机构信息均为虚构，仅用于本地教学演示。
- 新建空库时先执行 `01_schema.sql`、`02_seed.sql`，如需补充演示记录再执行 `06_demo_patients.sql`。03—05 是旧库迁移脚本，不要对已包含相应结构的新库重复执行。
- 06 脚本只能执行一次。执行前先核对 5 个账号、2 个医生编号及演示机构、套餐和检查项名称均不与库中现有记录冲突；如执行出错必须回滚，不要忽略错误继续运行。
- 新增演示机构与示例机构一样配置周一至周五每天 20 个名额，实际假日、医生排班与医疗数据需另行提供。

- `07_clear_sample_labels.sql`：只替换项目预置记录中符合原值的展示名称。本机已执行；对用户后来填写的报告标题和结果不做批量替换。

演示数据库中的患者、医院、医生、检查项目和报告均为项目内编写的虚构资料；页面使用的普通名称及检查结果不代表真实机构、人员或医疗结论。


## 预约支付、服务与密码找回

- `10_appointment_payment.sql`：已有数据库一次性增加体检订单的模拟支付状态与金额；原有预约按已支付保留。空库的 `01_schema.sql` 已包含这些字段。
- `11_password_reset.sql`：已有数据库一次性增加密码找回申请表；空库的 `01_schema.sql` 已包含该表。
- `12_services_shop.sql`：已有数据库一次性增加服务申请、健康记录、电子商品与商城订单表及初始电子资料；空库的 `01_schema.sql` 已包含这些内容。
- 执行旧库迁移前请检查表和字段是否已经存在，避免重复执行。本机数据库已执行上述三项迁移。
- 体检订单未支付时占用预约名额，并阻止同一体检人重复预约；可以在我的预约取消，名额随即释放。取消已模拟支付的预约后记录为已模拟退款；不会产生真实交易。

- `13_doctor_account_mapping.sql`：已有数据库将排班编号关联到医生账号；原照片身份未核实，不作为医生头像。新库的 `01_schema.sql`、`02_seed.sql` 和 `06_demo_patients.sql` 已配置对应关系，不要重复执行 13。
- `14_expand_check_items.sql`：在套餐中添加尿常规、空腹血糖、心电图，适用于旧库或完成种子数据的新库；只影响新生成的报告模板，不修改历史报告。参考范围由实际检验报告决定。

- `15_doctor_profiles.sql`：增加 5 个项目用医生账号与 8 份服务资料，并关联排班。旧库及新库均需在 `01_schema.sql`、`02_seed.sql`、`06_demo_patients.sql` 后执行；不覆盖原有医生账号或资料。本机已执行。新增账号 `doctor04`—`doctor08` 的初始密码与测试医生 `doctor02` 相同，仅供本地项目使用。

- `16_expand_exam_details.sql`：补充血脂、内科、肝肾功能检查及一般检查、血常规、尿常规等明细，并关联套餐；不修改已生成的报告。本机已执行。新库按顺序执行 `01_schema.sql`、`02_seed.sql`、可选 `06_demo_patients.sql`，再执行 `14_expand_check_items.sql`、`15_doctor_profiles.sql`、`16_expand_exam_details.sql`。新增参考范围以实际检验报告为准。
